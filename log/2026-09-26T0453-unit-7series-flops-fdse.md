rejects it (the model raises before any output); both `iverilog` and `xsim` instead
run to completion (`XUT_DONE`) with no error —

(INIT)"` in both `result.json`s. This is the same gap the generated test already
documents ("whether UNISIM rejects it is observed, not documented (see Task 24)").

'7series.FDRE.L0.illegal_init' --runner iverilog --runner xsim`, reproduces the
identical `fail`/reason on both runners for FDRE too — this is a UNISIM/FD*-wide
behaviour (UNISIM silently accepts `INIT=1'bx` at simulation time; nothing in UG953
says it is rejected), not a bug introduced by the FDSE model or test. Left for Task
24 to classify (likely `doc-gap`) and file across all four flops in one findings
pass, per Ruling S39.

**iverilog vs xsim agreement on the sv checkpoints:** both pass and their traces
