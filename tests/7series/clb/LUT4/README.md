# LUT4 — 4-input look-up table

UG953 v2026.1, section LUT4, pages 497–499 (CLB / LUT). Work unit: `luts`. GENERATED by `_shared/luts/luts_tests.py`.

## Overview

LUT4 reads a 16-bit INIT at the address formed by its inputs; it has no clock and no state. Behavioural claims are in `catalog/7series/LUT4.overrides.yaml`.

## Why each test is useful, and what it misses

- `7series.LUT4.L0.smoke`: Elaborates with the default INIT and two sampled ones and reads every address: the minimum any toolchain must get right. The default configuration sets no attribute, so the model's documented default meets the simulators' own.
  - Misses: one sweep per configuration
  - Misses: no x/z on any input (sv_x_inputs covers x)
  - Misses: illegal values are tried only by L0.illegal_init
- `7series.LUT4.L0.illegal_init`: An INIT with x digits is not the HEX value UG953 asks for (p499); the simulation must reject it (expect=reject), the runtime-rejection path of spec §4.1.
  - Misses: only an all-x INIT is tried; an over-wide literal is refused by xut wrap
  - Misses: whether UNISIM rejects it is observed, not documented (Task A6 rule)
- `7series.LUT4.L1.default_init`: INIT unset: every address reads 0 (a ground, per the Introduction); a flow that drops or mangles the default fails here.
  - Misses: the default is the only value; explicit zero is in L2.init_sweep
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.LUT4.L1.projections`: INIT chosen so the output equals one input (and its complement), for every input: pins the input-to-address order of the logic table; a swapped pair fails at once.
  - Misses: single-input functions only; general INITs are in L2
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.LUT4.L1.gsr_transparent`: Inputs move while GSR is asserted. UG953 names no GSR effect on a LUT, so the model infers the table holds (inferred:, no claim, ruling S44): a disagreement is a doc-gap finding, never masked.
  - Misses: claims are credited only by the sweeps before and after the pulse
  - Misses: one GSR pulse, one configuration
- `7series.LUT4.L2.init_sweep`: Spec §4.2 INIT sampling (boundaries, walking ones and zeros), each read at every address: every INIT bit is seen alone, set and clear.
  - Misses: the addresses are visited in binary order (L2.init_random adds random order)
  - Misses: no x/z on any input (sv_x_inputs covers x)
  - Misses: propagation delay is not measured (timing is out of scope, spec §2)
- `7series.LUT4.L2.init_random`: Seeded random INITs, each swept and then read at random addresses, where several inputs change at once.
  - Misses: one seed per run; a failing seed is frozen by hand (xut freeze-seed is deferred)
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.LUT4.L1.sv_x_inputs`: Every defined address is checked against the logic table; x on each input, where the two INIT bits it selects agree and where they differ, is recorded as checkpoints: UG953 does not define x behaviour, so crosscheck compares simulators.
  - Misses: x behaviour is undocumented: checkpoints only, never checks
  - Misses: no z inputs
- `7series.LUT4.L1.sv_gsr_midsim`: The logic table is checked before and after a GSR pulse; the output while GSR is asserted is a checkpoint (UG953 names no GSR effect on a LUT).
  - Misses: the GSR effect is undocumented: checkpoints only
  - Misses: one configuration
- `7series.LUT4.L2.cocotb_random`: Long model-checked random sessions on Icarus and Verilator; a failing seed is frozen into a vector test that also runs on xsim and hardware.
  - Misses: no GSR mid-session
  - Misses: 4 configurations
  - Misses: no x/z on any input (sv_x_inputs covers x)
