# FDCE — D flip-flop with clock enable and asynchronous clear

UG953 v2026.1, section FDCE, pages 369–370 (REGISTER / SDR). Work unit: `flops`. GENERATED by `_shared/flops/flop_tests.py`.

## Overview

FDCE is a single D flip-flop with clock enable and an asynchronous clear input `CLR` that drives Q Low. GSR loads INIT. Programmable inversion exists on C, D and the control pin. Behavioural claims FDCE.C1–C8 are in `catalog/7series/FDCE.overrides.yaml`.

## Why each test is useful, and what it misses

- `7series.FDCE.L0.smoke`: Every one of the 16 attribute combinations elaborates, powers up to INIT and captures once on every simulator: the minimum any toolchain must get right.
  - Misses: only one capture per configuration; no control, CE-low or GSR activity
  - Misses: no x/z on any input (sv_x_inputs covers x)
  - Misses: illegal values are tried only by L0.illegal_init
  - Not on hw for configurations `*_d1_*`: IS_D_INVERTED=1 (UG953 p370) is only legal on I/O registers; the fabric harness uses SLICE flops
- `7series.FDCE.L0.illegal_init`: INIT=1'bx is outside UG953's 1'b0/1'b1 (p370); the simulation must reject it (expect=reject), which exercises the runtime-rejection path of spec §4.1.
  - Misses: only INIT=1'bx is tried; over-width literals are truncated at elaboration and IS_*_INVERTED illegal values are not tried
  - Misses: whether UNISIM rejects it is observed, not documented (see Task 24)
- `7series.FDCE.L1.capture`: Pins the basic D-to-Q transfer on the active edge, for both INIT values and for the all-defaults configuration (model defaults vs UNISIM defaults).
  - Misses: CE held High and the control inactive throughout
  - Misses: no GSR after power-up
  - Misses: default polarities only
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.FDCE.L1.ce_hold`: Shows that CE Low makes clock edges no-ops even with D different from Q.
  - Misses: CE never toggles within a cycle (between edges only)
  - Misses: control inactive
  - Misses: default polarities only
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.FDCE.L1.clear_over_ce`: CLR must win over CE Low and over D, at once, with no clock edge. A priority inversion here is a classic synthesis-mapping bug.
  - Misses: CLR release timing relative to the clock is covered only by clear_recovery
  - Misses: default polarities only
  - Misses: no x/z on any input (sv_x_inputs covers x)
- `7series.FDCE.L1.clear_async`: CLR acts without any clock edge, repeatedly, from both Q values.
  - Misses: no clock activity while the control is asserted
  - Misses: no GSR overlap
  - Misses: default polarities only
- `7series.FDCE.L1.clear_recovery`: After CLR is released, the next active edge captures D. The edge is at least async_sep_ps after the release, so recovery timing is not tested (spec §2).
  - Misses: recovery/removal timing is out of scope (spec §2)
  - Misses: one release per configuration
- `7series.FDCE.L1.gsr_init`: A GSR pulse mid-run returns Q to INIT from the opposite value; checks glbl handling in every simulator and, later, every flow's INIT mapping.
  - Misses: GSR overlapping an active control is not driven here
  - Misses: edges during GSR are an inferred behaviour (see sv_gsr_midsim)
- `7series.FDCE.L1.is_c_inverted`: Samples after both edges show capture only on the falling edge.
  - Misses: CE High and control inactive throughout; the other inversions stay 0 (combinations are in L2.exhaustive)
- `7series.FDCE.L1.is_clr_inverted`: CLR held Low acts as active; a flow that drops the inversion fails at once.
  - Misses: one assertion per configuration; other inversions stay 0
- `7series.FDCE.L1.is_d_inverted`: Q takes the complement of D.
  - Misses: claim:FDCE.C8 — IS_D_INVERTED=1 is only legal on I/O registers; a placement rule for hardware flows (steps 3-4), not a simulation behaviour
- `7series.FDCE.L2.exhaustive`: Every attribute combination x prior Q x (control, CE, D): the complete single-edge truth table.
  - Misses: single edge per combination: no multi-cycle ordering (see L2.random)
  - Misses: no GSR (L1.gsr_init and sv_gsr_midsim cover it; hardware GSR needs §7.2)
  - Misses: no x/z on any input (sv_x_inputs covers x)
  - Not on hw for configurations `*_d1_*`: IS_D_INVERTED=1 (UG953 p370) is only legal on I/O registers; the fabric harness uses SLICE flops
- `7series.FDCE.L2.random`: Seeded constrained-random sequences find ordering effects that the single-edge table cannot.
  - Misses: no GSR (hardware GSR needs §7.2; L1.gsr_init covers simulation)
  - Misses: one seed per run; failing seeds must be frozen by hand (xut freeze-seed is deferred)
  - Misses: no x/z on any input (sv_x_inputs covers x)
  - Not on hw for configurations `*_d1_*`: IS_D_INVERTED=1 (UG953 p370) is only legal on I/O registers; the fabric harness uses SLICE flops
- `7series.FDCE.L1.sv_gsr_midsim`: Direct UNISIM instances for both INIT values; glbl GSR is forced mid-run while clocking. Edges during GSR are recorded, not judged, because UG953 is silent.
  - Misses: behaviour of clock edges while GSR is active: undocumented, checkpoint only
  - Misses: default IS_* polarities only
  - Misses: control inactive throughout
- `7series.FDCE.L1.sv_x_inputs`: X on D, CE or the control: the documented cases (CE Low holds; the control overrides) are checked; the undocumented ones are recorded for cross-simulator comparison. Not run on Verilator: see unsupported_reasons (plan ambiguity 9).
  - Misses: UG953 does not define X behaviour; X on D with CE High, X on CE and X on the control are checkpoints only
  - Misses: no x on C
  - Misses: default polarities only
- `7series.FDCE.L2.cocotb_random`: Long model-checked random sessions on Icarus and Verilator; any failing seed becomes a frozen vector test that also runs on xsim and hardware.
  - Misses: no GSR mid-session
  - Misses: only 4 of the 16 attribute configurations
  - Misses: no x/z on any input (sv_x_inputs covers x)

## Oracle

- Vector tests: the clean-room golden model `models/xut_models/7series/fdce.py` (shared logic in `_common/flops.py`), written from UG953 alone. Every expected bit carries `doc:<page>` or `inferred:<reason>`, and bits UG953 leaves undefined are `-`.
- sv tests: self-checks of documented behaviour only; undocumented X and GSR cases are checkpoints compared between simulators by `xut crosscheck`.
- cocotb: the same golden model, cycle by cycle.
- References: UNISIM on xsim, Icarus and Verilator (after `xut verilatorize`, guarded by its Icarus equivalence check).
